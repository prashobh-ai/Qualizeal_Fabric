# T83 — Audience coverage matrix (the completeness check)

One test and one Admin panel that prove every audience is served across every
data type the fabric holds.

## What it is

- **`eval/coverage.py` + `eval/sets/coverage.jsonl`** — the matrix is data type
  (13 rows: website, products, case studies, code, PRs/commits, architecture,
  dependencies, Jira, Confluence, tables, documents, images, HR) × persona
  (business, developer, tester, architect, curator, HR). `MATRIX` maps each data
  type to the personas that should reach it — the ✓ cells; `coverage.jsonl`
  holds the questions per cell.
- **Grading** runs each cell's questions through the ONE governed answer path
  (`AnswerService.ask`) as that persona, and checks the answer is grounded and
  cited **and cites that data type's own document** — the data type actually
  served that audience, not a lookalike. A cell is **green** (all questions
  pass), **amber** (some), **coral** (a held data type answered none), or
  **n/a** (the fabric does not hold that data type).
- **Self-contained corpus.** Like `eval/fixture.py` derives `facts.jsonl`,
  `coverage.py` ships one public document per data type (each with a title token
  distinctive across the corpus) that every question grounds in. `build_fabric`
  ingests it and `held` reports exactly the data types it put in the fabric, so
  the gate — *no coral cell for a held data type* — is exact and needs no live
  source. A general fabric with no coverage corpus reports every cell n/a rather
  than coral.

## Surfaces, MCP, gate

- **Admin → Coverage** (`GET /admin/coverage`, via `fabric_views.coverage_matrix`)
  renders the matrix as a heatmap: green / amber / coral / grey per cell, the
  gate verdict, and a click on any cell opens its questions and last results.
  Served from a generated `data/coverage.json` when present, else computed once
  and cached.
- **MCP** `coverage_status()` returns the matrix and gate verdict so an agent
  can see where the fabric is thin for any audience.
- **Gate.** `tests/test_coverage.py` runs the evaluation and asserts no coral
  held cell and that every held ✓ cell is green — this is the CI gate. A guard
  test feeds an ungroundable question and proves a broken cell turns the gate
  coral. `make coverage` runs it and writes `data/coverage.json`.
- **Showcase.** `/admin/coverage` is baked into the admin bucket (the endpoint
  computes the matrix over the self-contained corpus), so the static Admin
  heatmap renders the same matrix.

## Verification

`tests/test_coverage.py`:

- **gate** — no coral cell for a held data type; the report passes.
- **every held cell green** — each ✓ cell of a held data type answers, grounded
  and cited, for its persona.
- **completeness** — the matrix spans every data type and only known personas.
- **regression guard** — an ungroundable question for a held cell turns that
  cell coral and fails the gate, so the gate actually guards.

`make coverage` prints 55 green · 0 amber · 0 coral · 0 n/a (PASS). Full
`pytest` green; `ruff` clean; the coverage matrix bakes into the showcase Admin
