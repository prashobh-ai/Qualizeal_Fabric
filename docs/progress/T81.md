# T81 — Answer-first, explain-on-demand

An answer now returns in two parts. The direct `result` is composed and
rendered immediately; the narrative `explanation` is a second, optional step.

- `Answer` gains `result`, `explanation`, `explain`, `governance` (all in
  `to_dict`). `result` is the composed answer — a facts/KPI answer already
  costs no model tokens on the extractive floor. `explanation` stays null
  until asked.
- `AnswerService.explain(trace_id)` recovers the question from the answer span
  (stored as `question` on the trace) and produces the working — the
  selector's reasoning, the direct answer, and the numbered evidence — as a
  **separate ledgered step**: an `api_ledger` row with `purpose=explain` (the
  purpose is registered) plus a `kf.explain.requested` signal on the trace, so
  Admin can read the share of answers a reader asked to explain.
- `POST /api/explain {trace_id}` exposes it. The Workspace card shows the
  persona's `Explain` offers (T84); each fires this call and appends the
  narrative to the turn. `engine.js` serves `/api/explain` browser-side from
  the last answers, model-free, for the static showcase.
