# T30 — Telemetry fields

The telemetry spine and the self-serve Explorer (T29) could slice
role × level × model × language × complexity × kind. But the answering features
shipped since — persona/designation conditioning (T27) and two-turn context
resolution (T26) — left no trace in telemetry, so you couldn't ask "how do CxO
answers compare to developer answers?" or "how often does a follow-up actually
resolve?". T30 adds those as **first-class telemetry dimensions**.

## The new fields

Stamped on the parent **answer span** (so every answer path — compose, code,
discovery, reasoned, cache — inherits them) and surfaced in
`telemetry.events()`:

| Field | Meaning | From |
|---|---|---|
| **persona** | the profile the designation mapped to (builder/quality/…) | T27 |
| **designation** | the reader's org title (Developer, CTO, …) | T27 |
| **scope** | the access tier the answer ran under (public / restricted) | ACL |
| **context** | `resolved` when a follow-up was rewritten from the conversation, else `direct` | T26 |

`persona`/`designation`/`scope`/`context_resolved` ride the answer span's attrs;
`events()` reads them straight from the stored attrs (no schema migration), and
`analytics()` rolls up two headline metrics from them:

- **`answers_by_persona`** — the volume split across personas;
- **`context_resolution_rate`** — the share of answers that resolved a follow-up.

## Where they show up

- **Explorer** (dashboard): the four new dimensions join the `DIMS` list, so any
  permutation now includes Persona · Designation · Scope · Context — filter,
  group-by and pivot them beside the existing dimensions, live in the browser.
- **Analytics API** (`/api/analytics`): `answers_by_persona` and
  `context_resolution_rate` in the payload.
- **Showcase**: the build already drives every designation (T27), and now also
  drives a handful of two-turn follow-ups, so the baked telemetry carries a real
  persona spread and both `resolved` and `direct` context rows.

## Done-when

- Every answer records its persona, designation, scope, and whether it resolved
  a follow-up; the Explorer can filter and group by each. ✓
- A context follow-up records `context=resolved`; a plain ask records `direct`. ✓
- Analytics reports `answers_by_persona` and `context_resolution_rate`. ✓
