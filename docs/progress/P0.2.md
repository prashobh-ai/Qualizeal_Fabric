# P0.2 — Profiles and extras

Two profiles behind the SAME adapter contracts (ADR-0001):

- `KF_PROFILE=lite` (default) — stdlib-only, SQLite/FS/hash-embedder/mock model
- `KF_PROFILE=full` — Postgres + pgvector + pg_trgm, an OpenTelemetry
  Collector, Jaeger for traces, Prometheus for metrics; same image, same code

Nothing about the contract shape, the invariants (I1–I14), or the application
code changes between them — only groups of environment variables set on
container start.

## Deliverables

| File | What it declares |
|---|---|
| `pyproject.toml` | Python 3.11 project + optional extras `[engines]`, `[db]`, `[otel]`, `[providers]`, `[connectors]`, `[speech]`, `[dev]`. Runtime deps stay empty (stdlib-only). All licences permissive. |
| `knowledge_fabric/app.py` | `Platform.profile = KF_PROFILE` — the only piece of application-visible state; consumed by adapters that need to know whether a real engine is expected. |
| `Makefile` | `PROFILE ?= lite`, exported as `KF_PROFILE`. New targets `compose-up`/`compose-down` route through `docker compose --profile`. |
| `deploy/compose/docker-compose.yml` | Two compose profiles (`lite`, `full`). Fabric service is in both; `postgres`, `otel-collector`, `jaeger`, `prometheus` are `full`-only. Image is one image; `KF_EXTRAS` build arg pulls the DB driver + OTel client only when needed. |
| `deploy/compose/otel-collector.yaml` | OTLP/HTTP receiver → Jaeger (traces) + Prometheus (metrics). Vendor-neutral. |
| `deploy/compose/prometheus.yml` | Scrapes the collector's Prometheus exporter + fabric's `/metrics`. |
| `ci/licence_manifest.json` | Every new package in the extras declared with `optional-runtime` linkage and a permissive licence; the licence gate stays green. |
| `scripts/licence_gate.py` | Strict pyproject scan — reads only `[project] dependencies` and each array under `[project.optional-dependencies]`; ignores every other TOML table. |

## Extras groups (all permissive)

- `engines` — docling, sentence-transformers, torch, transformers,
  lingua-language-detector, spacy, tiktoken
- `db` — pg8000 (BSD-3, not psycopg)
- `otel` — opentelemetry-{api, sdk, exporter-otlp-proto-http, semantic-conventions, instrumentation}
- `providers` — openai, boto3
- `connectors` — msal, atlassian-python-api, google-api-python-client,
  PyGithub (LGPL, external-service-only)
- `speech` — faster-whisper, silero-vad, kokoro, soundfile, numpy
- `dev` — ruff, mypy

## How the profile flips adapters

`Platform.__init__` still resolves each adapter from env. The profile just
sets *groups* of these env vars — nothing else. For `full`:

- `KF_DB_URL=postgres://…` → `cloud.build_database` returns `PostgresNotice`
- `KF_OTLP_URL=http://otel-collector:4318` → `otel_export.to_otlp` targets the collector
- `KF_EXTRAS="boto3 pg8000 opentelemetry-*"` at image-build time pulls the
  packages behind the guarded imports

Missing packages still degrade to stdlib rather than crashing (tests skip;
adapters raise `CloudNotReady` / `OIDCNotReady` only when actually used).
