# T34 — Answering-intelligence demo (the T24–T33 capstone)

`scripts/demo.py` narrates the platform **fundamentals** (ingest → cited answer →
honest refusal → tenant isolation → budget cap → promotion gate → economics).
The T24–T33 series then built an **answering-intelligence** track on top of that
floor — discovery, code answers, two-turn context, role framing, telemetry
dimensions, an MCP surface, static parity and a load gate. Those shipped one PR
at a time; nothing yet told them as one story. T34 is that capstone: a single
runnable narrative a stakeholder can watch end to end.

## What it shows

`scripts/demo_answering.py` seeds one small, self-contained fabric (two products,
two code files, an SSO policy) and walks every capability the series added, in
order, against the **real `AnswerService`** — not a mock:

| Beat | Feature | What the reader sees |
|------|---------|----------------------|
| 0 | The floor | a grounded, cited answer and an honest out-of-corpus decline |
| 1 | **T24** discovery | "has anyone made sso/auth code I can reuse?" → a ranked, cited asset list |
| 2 | **T25** code answers | "how does `retry_call` work?" → the source in a code block at an exact locator |
| 3 | **T26** two-turn context | "what about its pricing" resolved to `understood_as: what about QMentisAI pricing` |
| 4 | **T27** role-conditioned | one question, one evidence set, a different lens/depth/emphasis per designation |
| 5 | **T30** telemetry | every answer above as one Explorer row — persona / scope / context as first-class dims |
| 6 | **T31** MCP parity | a least-privilege agent hits the SAME governed path, audited as an agent (no back door) |
| 7 | **T28** quality gate | the golden suite passes (12/12), by dimension |
| 8 | **T32** static parity | the shipped `engine.js` answers like the server (runs when Node is present) |
| 9 | **T33** load | a small concurrent burst meets the SLOs (QPS, p95, zero errors/throttles, unique traces) |

It runs on the **model-free extractive path** (`KF_MODEL_MODE=off`, the deployed
floor), so it is deterministic, needs no credits, and shows exactly what ships —
not a model-dependent best case.

## Doubles as a smoke check

The script isn't only prose: beats 7 and 9 call the real quality suite and the
real load gate, and `main()` returns non-zero if either regresses. So the same
narrative is a fast end-to-end smoke check — which is why it runs in CI.

## Where it runs

- **`make demo-answering`** — the local one-liner (`scripts/demo_answering.py`).
- **`.github/workflows/ci.yml`** — an *Answering-intelligence demo (T34)* step in
  the `lite` job, beside the existing fundamentals demo. The parity beat skips
  cleanly when Node is absent (the `mcp` job runs the real parity check).
- **`tests/test_t34_demo_answering.py`** — runs each beat against the service
  (discovery lists assets, code answers carry a block, coreference resolves,
  designations yield distinct lenses, the MCP agent is audited as an agent) and
  asserts `main()` exits zero with the story reaching its final beat.

## Design notes

- **One fabric, real service.** Every beat asks the same `AnswerService` the HTTP
  surfaces, the MCP server and the showcase use — the demo can't drift from what
  ships because it *is* what ships.
- **MCP without the optional extra.** Beat 6 reuses `mcp.server._agent_principal`
  (the exact principal the MCP `ask` tool mints) and the one service, so it
  demonstrates the governed agent path without requiring the optional `mcp`
  package to be installed — honest parity, no heavyweight dependency.
- **Kept separate from `demo.py`.** The fundamentals demo and the answering demo
  are two focused stories, not one 30-section wall; each stays legible.
