# T29 — Self-explaining dashboards + the telemetry Explorer

Two things: the analytics panels now explain themselves, and a new **Explorer**
tab puts every telemetry dimension in one filterable, pivotable table — so any
permutation (role × level × model × language × complexity × kind) can be sliced
in one place, alongside the existing purpose-built tabs, not instead of them.

## The Explorer (one table, every permutation)

A new "Explorer" tab on the telemetry dashboard reads flat per-answer telemetry
and does all the work client-side:

- **Filter** any dimension by clicking its values (multi-select chips); leave a
  dimension untouched to include all. Filters combine across dimensions.
- **Group by** any one or two dimensions.
- **Metrics** per group: Questions, Answered, Declined, Cited %, Trust, Tokens
  in/out, Cost, Saved, p95 latency — with a live Total row. Click a column to
  sort.

The data contract is `telemetry.events()` → one row per answered question with
every dimension beside every metric, served at `/api/events` (curator+), and
baked into the showcase snapshot so the static demo pivots live in the browser.
The build drives a broad question spread across every role so the Explorer has
real volume (~320 events in the full build).

## Self-explaining panels

Every headline panel now carries three things (T29):
- a plain-language **title** (the question it answers),
- a one-line **reading line** (what the number means / what to watch),
- a **`?`** that opens a definition sheet: what it counts, how it is computed,
  and what to do when it moves.

Definitions live in one `DEFS` map and are shared by the KPI tiles (Answers,
Cost, Saved, Trust, Citation coverage, p95 latency, Clarify-back), the routing
and savings panels, and the Explorer.

## Done-when
