# T55 — Token-meter telemetry

`knowledge_fabric/telemetry/insights.py` reconciles the API ledger into the
panels an operator reads, every number a ledger sum by construction:

- `overview(days)` → `totals`, `cost_breakdown` (cost by phase), `efficiency`
  (cited output tokens / total tokens), `provider_quota` (the active
  provider's limit — "unlimited (local)" for open-source), `burn_rate`
  (cost per hour + projected per day) and `per_dimension`.
- `definitions()` feeds the "?" sheet so every panel explains itself.

`GET /admin/models` carries `telemetry` + `definitions` + the honest
`provider_badge` alongside the existing provider card and consumption tables;
the Admin → Models console renders the overview as a chip row.

The concepts (cost by phase, active-vs-idle, waste, efficiency, per-phase
cost, provider quota, percentile timing) are reimplemented from the
MIT-licensed *token-meter* project — clean-room, no code copied — credited in
`docs/CONCEPTS.md` and `THIRD_PARTY_NOTICES.md`.
