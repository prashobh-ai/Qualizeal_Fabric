# T25 — Code into the fabric

Code questions now answer with the actual function and a line-anchored GitHub
link, on both the server path and the baked static showcase. No model is used
for code (never paraphrase code); no external token is needed — the showcase
ingests this repository's own checked-out source.

## What shipped

**Symbol chunking (`adapters/converter.py`).** `_code` parses Python with `ast`
and emits one passage per top-level function, per class (its docstring), and per
method. Non-Python / unparseable source uses a brace-and-keyword scanner with a
40-line window bound. Every code passage carries a rich `SYMBOL_LINE` locator:
`symbol`, `line` (back-compat), `qualified`, `start_line`, `end_line`, `path`,
`repo`, `language`, a deterministic `summary_line` (signature + first docstring
sentence, no model), and a GitHub `url` anchored to `#L<start>-L<end>`.

**Ingestion (`scripts/build_showcase.py`).** `_load_code` ingests a curated set
of this repository's Python files through the real pipeline, tagged
`github://prashobh-ai/Qualizeal_Fabric/<path>`, plus one deterministic
repository-overview document (`_repo_card`) that answers "what does this repo
do". A `github-code` connector row appears in the Admin console.

**Identifier tier (`answer/service.py`).** A code question names a symbol, which
the semantics-free hashing embedder routinely misses. `_code_answer` is an early,
decisive path: it scans code passages, and on a symbol-name hit answers directly
at Level 1 from the top matching functions — before the prose grounding/clarify
machinery, which is tuned for prose. `_ident_score` weights a symbol hit over a
qualified-name hit over a path hit, so the exact function ranks first. A question
naming a distinctive *prose* subject (a product/company doc) is left to the prose
path.

**Code answer shape (`_compose_code`).** A one-line deterministic summary then
the cited function verbatim in a fenced block; at most two blocks; the model is
bypassed entirely.

**Subject reliability (`_subject_boost` inject, `_ensure_subject`).** When
retrieval misses a distinctive subject document (a weakly-worded title the
embedder never surfaces — e.g. the repository card), its passages are injected
into the candidate set and one is guaranteed a place in the MMR selection, so the
`_exact_signal` grounding floor can answer it.

**UI (`ask_ui__js.js`, `ask_ui__css.css`).** `renderAnswer` renders fenced code
blocks verbatim; a code citation chip links straight to the exact lines on
GitHub; document citation chips still open the passage viewer.
