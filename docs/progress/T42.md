# T42 — Facts and table queries (Level 0)

`data/facts.json` — the exact, as-of-dated numbers the fabric knows:
`repositories` (T37), `jira_projects` (T41), `confluence_spaces` (T41),
`documents` (`facts/build.py`, from the document store: by area, by type,
total), `tables` (T41). `knowledge_fabric/facts/` reads them by their pinned
schemas; `capabilities.json`, `dependencies.json` and `analysis/<repo>/`
beside them.

`knowledge_fabric/answer/aggregate.py::try_answer` is the Level-0 ladder the
answer service consults BEFORE retrieval: entity resolution (repository /
project / space / sheet — aliases, pronouns from the conversation, a clarify
when ambiguous), then the pattern handlers — examples of a symbol, reusable
components, CSS files, licences, enterprise readiness, architecture /
retrieval techniques, who (contributors), repository facts (commits,
contributors, PRs, languages, deployments, releases, workflows), Jira
(totals, open, bugs, a named priority / status / type / assignee value, by-X
breakdowns, sprint, live JQL when the facts are older than an hour), Confluence,
sheets, capabilities ("do we have any RAG implementation"), inventory
("how many repositories / documents do we have"). Every answer states the
as-of time and cites the source (facts row, manifest, symbol line, sheet).

`knowledge_fabric/answer/tables.py` answers sheet questions with ONE `SELECT`
over `tables/<doc>/<sheet>.sqlite` (count / sum / avg / min / max, GROUP BY,
filters), cited to the sheet and row.

## Verification

`eval/quality.py --sets facts tables jira` on the fixture: 50 / 50 facts
(the ten questions + 40 variants), 20 / 20 tables, 10 / 10 Jira —
`false_answer_rate = 0`, `exact_count_accuracy = 1.0`. `make demo` beats 3–5.
