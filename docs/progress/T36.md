# T36 — Real consumption on every dashboard

## The ledger

`knowledge_fabric/telemetry/api_ledger.py` appends one row per model call to
`data/api_calls/<day>.jsonl`:

`{ts, run_id, workflow, purpose, model, repo, doc_id, question_hash, input_tokens,
output_tokens, cache_read_input_tokens, cache_creation_input_tokens, latency_ms,
cost_usd, request_id}`

`purpose` ∈ `repo_summary | capability_classify | answer_bake | ask_queue |
agent_step | translate | image_describe | question_gen | table_sql |
quality_harness | doctor_ping` (an unknown purpose is recorded as
`unknown:<p>`, never dropped). `run_id` is the Actions run id (or a
per-process id), `workflow` the Actions workflow (or `local`), `request_id`
the provider's `request-id` header.

Every call goes through `AnthropicModelClient.messages(body, purpose, …)` —
text, images, tools, `cache_control` — so nothing can bypass the ledger.
The answer service passes `purpose` from `KF_LEDGER_PURPOSE` (`answer_bake`
in the showcase build, `ask_queue` in the queue) and a `question_hash`.

## Prices

`knowledge_fabric/telemetry/prices.json` (USD per million tokens, maintained
by hand; shown on Admin → Models), overridable by `data/prices.json` in a
`fabric-data` checkout:

| model | input | output | cache read | cache write |
|---|---|---|---|---|
| claude-sonnet-4-6 | 3.00 | 15.00 | 0.30 | 3.75 |
| claude-haiku-4-5 | 1.00 | 5.00 | 0.10 | 1.25 |

`cost_for(model, usage)` prices the real usage block.

## Dashboards read the ledger

`api_ledger.consumption(days)` → totals, by day / purpose / model / repository /
workflow, last 50 calls, prices. `GET /admin/models` serves it beside the
provider card; Admin → Models renders it (window 24h / 7d / 30d). Because the
totals and every breakdown are sums over the same rows, the dashboard totals
equal the ledger sums by construction (a test asserts every breakdown sums
back to the totals).

The run summary (`step_summary_line`) and the dashboard read the same rows,
so they agree.
