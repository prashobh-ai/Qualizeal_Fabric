# T28 — Answer-quality golden suite + CI gate

The platform already had a **promotion gate** (`evaluation/gate.py`) that guards a
candidate *index version* against the question bank. T28 adds the complementary
guard: a curated **golden suite** that pins the answering *behaviours* the
product promises and fails the build when any of them regresses — so the work in
T24–T27 can't silently rot.

## What it checks

`knowledge_fabric/evaluation/quality.py` ingests its own tiny corpus through the
real pipeline, then runs a set of **hard must-hold** cases against the governed
answer path with the **model disabled** (`KF_MODEL_MODE=off` — the deployed
extractive floor). Twelve golden cases across eight dimensions:

| Dimension | Golden case(s) |
|---|---|
| **answering** | a grounded answer with citations |
| **grounding** | grounding score above the floor |
| **citations** | every citation resolves to a place; the subject document is cited |
| **decline** | an out-of-corpus question is declined, not hallucinated |
| **code** | a code answer quotes the function verbatim and links its exact lines (`#L`) |
| **discovery** | "has anyone made auth code I can reuse" returns a ranked asset list |
| **context** | a two-turn follow-up resolves the subject; a bare pronoun with no session asks back |
| **persona** | designation shapes depth (CTO headline vs developer full), leads the right evidence (developer→impl, tester→test), and stamps the right lens |

`run_quality_suite()` returns a `SuiteResult` — `passed` (True only when **every**
curated case holds), an overall `score`, per-dimension pass rates, and the list
of failures. A case that raises is recorded as a failure, never a silent pass.

## The gate

`scripts/quality_gate.py` runs the suite and **exits non-zero** on any regression
(`--json` for a machine-readable result). It is wired in three places:

- **`make quality`** — the local one-liner.
- **`make ci`** — folded in alongside `test` and `licences`.
- **`.github/workflows/ci.yml`** — a *Answer-quality gate (T28)* step in the
  `lite` job (SQLite, fast), so a PR that drops answer quality fails CI at the
  same stage as the test suite.

## Done-when

- The golden suite passes green on a healthy fabric (12/12), covering every
  answering dimension T24–T27 shipped. ✓
- The gate **actually gates**: corrupting the citation coordinates makes the
  "citations resolve" case fail and the gate report FAIL. ✓
- `make quality` / the CI step exit non-zero on regression. ✓

## Verified

`tests/test_t28_quality.py` (6 tests: suite passes on a healthy fabric; every
dimension is covered; the report renders; the gate blocks a corrupted fabric; a
crashing case counts as a failure; the CLI exits 0 when healthy). Full suite
green (352); `ruff` clean; `make quality` and `python scripts/quality_gate.py`
exit 0. T28 is a server/CI change only — no showcase surface is affected.

## T28.1 — adversarial + invariant cases, per-dimension rollup

The original suite proved the system *answers*. T28.1 extends it to pin the
failures that actually hurt an enterprise deployment — the system must **refuse,
never leak, never drift** — and makes the gate's output diagnostic.

New golden cases (17 total now, up from 12):

- **`robustness`** — declines a plausible-but-absent subject ("what is NexaAI
  pricing"), and never fabricates a code answer for a symbol that does not exist
  ("how does `deploy_release` work" — a name that shares tokens with real code).
  Both must return a non-answer, not a hallucinated result.
- **`isolation`** — a **restricted** document (the "Zephyr / BLUEHERON" secret) is
  added to the eval corpus, and a public asker must never retrieve, cite, or echo
  it. This runs permission-before-ranking (I6) *inside the golden suite itself*,
  not only in the isolation unit tests.
- **`invariant`** — persona conditioning changes framing, **not the facts**: the
  lead cited document is identical across CTO / Developer / Curator for the same
  question. Depth may show fewer citations, but the evidence base never swaps.
- **`code`** — a second symbol in a second file (`mint_session_token` in
  `auth.py`) resolves and is anchored, so code answering isn't overfit to one
  function.

Report + machine-readable output:

- `format_report` now prints a **per-dimension rollup** (`✓ isolation 1/1`), so a
  regression names the offending dimension at a glance.
- `SuiteResult.to_dict()` carries `dimension_counts` and the full `rows`, and
  `scripts/quality_gate.py --json` emits it — ready for a dashboard or a CI
  artifact.

### Why these (and not a baseline-diff)

The suite is deterministic and all-must-hold, so a committed baseline of scores
would always read `1.0` and add no signal — skipped deliberately. The value is in
*what the gate enforces*, and these cases raise that bar from "does the happy
path work" to "does it refuse, isolate, and keep facts stable" — the properties
an enterprise actually audits.

### Verified (T28.1)

`tests/test_t28_quality.py` (11 tests now: the original 6, plus the new
dimensions are registered; the isolation case blocks a restricted leak directly;
every adversarial/invariant case holds on a healthy fabric; the report carries
the per-dimension rollup; `to_dict()` carries `dimension_counts` and `rows`).
`python scripts/quality_gate.py` → 17/17 PASS with the per-dimension rollup; full
suite green; `ruff` clean.
