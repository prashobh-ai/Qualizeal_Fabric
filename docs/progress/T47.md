# T47 — Surfaces

`knowledge_fabric/fabric_views.py` reads the `fabric-data` files for every
surface:

* **Workspace tiles** — `/api/corpus` adds `repositories`, `jira_projects`,
  `confluence_spaces`, `tables`, `images` beside the five original tiles.
* **Curator → Repositories** — one row per repository: language, commits,
  PRs merged, contributors, deployments, capability pills, enterprise score
  bar, last push, card / architecture flags, Delete; the card overlay shows
  facts, the languages bar, capability evidence, dependencies with licence
  pills, the architecture summary, contributors, recent PRs and commits (from
  the ingested `github://<repo>/pulls/<n>` and `/commits/<sha>` documents).
* **Curator → Insights** — capabilities across repositories + reuse candidates.
* **Curator → Tables** — sheets with columns and row counts, a read-only
  SELECT box (`/curator/tables/query`).
* **Admin → Sources** — GitHub / Jira / Confluence cards: last run, next run
  (refresh scheduler), counts (facts), GitHub rate limit remaining
  (`github_live.rate_limit_remaining()`).
* **Admin → Models** — the provider card (T35) and API consumption (T36).
* **Chatbot** — agent runs render `why.steps` as `Checked <tool> · <n>
  results` lines under the bubble; `KF.streamStep` appends them live.

The static showcase bakes every new route per role (`build_showcase.py`
`CURATOR_GETS` / `ADMIN_GETS`) so GitHub Pages renders the same panels.
