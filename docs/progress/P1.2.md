# P1.2 — Corpus tiles
Status: DONE

## Files created/changed

- `knowledge_fabric/surfaces/http_api.py` — added `GET /api/corpus`:
  asker-accessible endpoint that returns `{tenant, documents, passages,
  entities, relationships, domains}` for the caller's tenant. Restricted
  documents are still counted (the ACL gate lives at retrieval time, not
  at the tile level).
- `knowledge_fabric/surfaces/ask_ui.py` — five animated tiles inserted
  above the ask card. CSS uses the P1.1 brand tokens (blue / cyan /
  violet / pink / good) to colour the numbers; `animateNumber` runs on
  load and on every `KF_ON_SESSION` so a tenant switch refreshes the
  strip. On network error the strip stays silent — the answer card owns
  error messaging.
- `tests/test_stage2_ui.py::TestCorpusTiles` (new) — three tests:
  `/api/corpus` counts equal the store counts for the seeded tenant;
  unauthenticated access is 401; the Ask page ships the five tile ids
  and the `animateNumber` helper.

## Deferred

- **`qualizeal` tenant seeding by default.** The spec's acceptance line
  says "tiles equal the store counts for `qualizeal` after `make
  load-corpus`". `make load-corpus` still requires an explicit `DIR=…`,
  and the demo seed currently loads the Q-* synthetic tenants. Once P1.5
  or an earlier step teaches the platform to seed the `qualizeal` tenant
  on first boot the assertion holds automatically for any tenant; the
  present test already parametrises on the seeded tenant, so the shape
  is generic.
