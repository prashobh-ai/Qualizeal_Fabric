# T31 — MCP tools (the Knowledge Fabric over the Model Context Protocol)

The fabric already answered over HTTP and in the static showcase. T31 exposes
the **same governed answer path** over the Model Context Protocol, so an agent,
an IDE, or Claude Desktop can use the fabric through a standard tool interface —
and the CI `mcp` job's inspector conformance check (`tools/list`), stubbed since
T01, goes live.

## The server

`knowledge_fabric/mcp/` — `python -m knowledge_fabric.mcp` runs it over stdio.
`build_server(platform, tenant)` binds the tools to a fabric; `MCPServer`
(the mcp 2.x SDK) turns each decorated function's signature + docstring into a
tool schema.

Every tool runs through the **one** `AnswerService` — the same
permission-before-ranking, grounding gate, citation post-check and persona
conditioning as a human ask (I7). An MCP caller is never an ungoverned back
door: it gets the same grounded, cited answers and the same honest declines.

## The tools

| Tool | Does | Returns |
|---|---|---|
| **ask** | Ask a grounded question (optional `designation` conditions framing per T27) | the full `Answer` — text with `[n]` markers, citations (doc + coordinate), grounding, level, the why-card, or a clarify/gap when evidence is weak |
| **discover** | Find reusable assets across the org (code, tests, policies, learning) — T24 | a ranked, deduped list of assets, each with a link to its exact place when there is one |
| **corpus** | Read how large the accessible corpus is | documents, passages, entities, relationships, distinct sources |

Calls run as a least-privilege **agent principal** (public scope); the ACL gate
still lives at retrieval time, so MCP never widens what is retrievable.

## Guarded, optional, licence-clean

The `mcp` package is the **optional `mcp` extra**. The import is guarded inside
`build_server` (never at module load), so importing `knowledge_fabric.mcp`
never hard-depends on it and the shipped process stays lean. `mcp` (MIT) is
declared in the licence manifest as an optional-runtime dependency; the licence
gate confirms the guarded import.

## Done-when

- `python -m knowledge_fabric.mcp` starts a stdio MCP server; `tools/list`
  returns `ask`, `discover`, `corpus` with schemas (the inspector conformance
  check the CI `mcp` job runs). ✓
- `ask` returns a grounded, cited answer through the governed path — and
  declines out of corpus; `designation` conditions the framing. ✓
- `discover` returns ranked reusable assets; `corpus` reports the counts. ✓

## Verified

`tests/integration/test_mcp.py` (7 tests: lists the three governed tools with
schemas; `ask` returns a grounded cited answer and declines out of corpus;
`designation` conditions framing through MCP; `discover` returns ranked assets;
`corpus` reports counts; the entrypoint imports). The tests skip cleanly without
the extra, so `lite`/`full` stay green and the `mcp` job runs them for real.
Full suite green (**366** with the extra); `ruff` clean; the licence gate
passes with `mcp` as a declared, guarded optional-runtime import; a stdio
`initialize` → `tools/list` handshake against `python -m knowledge_fabric.mcp`
returns the three tools.

## Deferred (later Tnn)

MCP **resources** (exposing documents/passages as readable resources) and
**prompts** (a curated ask template) beyond the three tools; a streamable-HTTP
transport for a hosted deployment (the SDK supports it — stdio is what the
inspector and desktop clients use); and per-caller identity beyond the single
agent principal once an MCP auth story is set.
