# T53 — Two curation modes + the review gate

Every source is **automated** (new documents go live on ingest) or **manual**
(new documents wait in `review` until a curator accepts). The mode resolves as
source-override → tenant default → automated.

- `knowledge_fabric/curation.py` — `set_mode` / `set_default_mode` / `modes`;
  `on_ingest` settles a document to `live` (+`auto_kept` log) or `review`
  (+`ingested` log); `accept` / `reject` resolve a queued item; `review_queue`
  lists what is waiting with a score + keep/delete recommendation.
- **The gate:** `review_doc_ids(platform, tenant)` returns the ids held in
  `review`, and retrieval skips their passages everywhere an answer is
  assembled — the fused-candidate path, graph expansion, the code-early path
  (`answer/service.py`) and asset discovery (`answer/search.py`). A held
  document is never cited, never quoted, never surfaced.
- Surfaces: `GET /curator/curation-modes`, `GET /curator/review`,
  `POST /curator/curation-mode`, `POST /curator/review-decision`; the Curator
  console renders the mode toggles and the review queue with Accept / Reject.
- Fixed a latent ordering bug: the review queue read "latest event" by the
  random uuid `id`, which could leave a resolved review queued; it now orders
  by `(ts, rowid)`.

## Verification

`tests/integration/test_review_gate.py` proves a manual-review document is
never cited nor discovered and that acceptance makes the same content
answerable; `tests/unit/test_curation_modes.py` covers mode resolution and the
queue (deterministic across orderings).
