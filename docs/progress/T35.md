# T35 — Provider pinning and proof of use

## Why the key looked unused

Three silent fallbacks, now removed:

| Where | Before | Now |
|---|---|---|
| `adapters/model.py` `build_model_client()` | `anthropic` without a key → `MockModelClient()`; unset mode + no key → mock | `ProviderUnavailable` naming the secret. `extractive` (alias `off`) is the only keyless mode and must be explicit; `mock` is an explicit test double, never a fallback |
| `answer/service.py` `_compose()` | `except Exception:` → served the extractive draft under the real model's name | the provider error propagates out of `ask()` — a bake or a queued answer fails visibly |
| `scripts/build_showcase.py` | four bare `except Exception:` around `svc.ask` / the client | removed; a provider error stops the build with the response body in the log |

## The model ceiling (fixed decision)

`ALLOWED_MODELS = ("claude-sonnet-4-6", "claude-haiku-4-5")`. Large tier
`claude-sonnet-4-6`; small tier `claude-haiku-4-5` when the key lists it,
otherwise `claude-sonnet-4-6`. `resolve_models()` (env override → doctor's
`provider_status.json` → default) raises `ModelNotAllowed` on anything else, and
`AnthropicModelClient.messages()` refuses to send any other id.

## `scripts/doctor.py --require anthropic`

The gate every Actions run passes through first:

1. empty key → exit **2**, naming `ANTHROPIC_API_KEY`
2. `GET /v1/models` 401 → exit **3** `Key rejected`; records `models_available`
3. pins small/large; an env override outside the set → exit **4**; Sonnet 4.6
   not listed → exit **5**
4. `POST /v1/messages` (small model, `max_tokens: 8`, `ping`) non-200 → exit **6**
   with the body; the ping is ledgered as `doctor_ping`
5. writes `data/provider_status.json`
   `{provider, key_fingerprint, models_available, model_small, model_large, verified_at, ping_usage}`
6. appends `Provider: Anthropic · key …<last4> · small <id> · large <id> · ping <in>/<out> tokens`
   to `$GITHUB_STEP_SUMMARY`

## Proof the key was used in THIS run

`build_showcase.py` ends with the ledger line for its run id —
`API calls: <n> · input <t> · output <t> · cache read <t> · cost $<x> · model <id>` —
in the log and the run summary, and under `KF_MODEL_MODE=anthropic` exits **7**
when `n == 0`.

## On screen

* Every answer card shows `Model: <id from the response>` or `No model needed`
  (`ask_ui__js.js` `modelLabel`); only the explicit test double reads `demo model`.
* Admin → Models: the provider card (provider, key fingerprint, pinned models,
  verified-at, ping usage) and the API consumption (T36), served by
  `GET /admin/models` and baked into the static Admin page.

## Workflow

`showcase.yml` runs the provider check before the build and passes
`KF_MODEL_MODE=anthropic` + `KF_LEDGER_PURPOSE=answer_bake` + the secret to the
build — no "stays green either way".

## Local operators

`Makefile` exports `KF_MODEL_MODE ?= extractive`: local targets run the
extractive floor unless you export `anthropic` with a key. The application
itself never falls back.

## Verified

`tests/test_f0_providers.py` (rewritten to the loud contract) and
`tests/test_t35_t36_provider_ledger.py`: every doctor exit code with a fake
transport; the pin (haiku when listed, sonnet otherwise); the fingerprint
never contains the key; the summary line; `ProviderError` carries status +
