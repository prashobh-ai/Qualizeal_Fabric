# T87 — Context and memory across audiences (stored per-user defaults)

The article's context point — a question means different things to different
users — is our persona + one/two-turn context (T26/T27). This adds the missing
piece: **defaults a reader sets once** and the fabric applies to every answer
without re-asking.

## What a reader can set

`answer/defaults.py`, persisted per user (`tenant` + `subject`) to the
fabric-data runtime file `data/user_defaults.json` (honours `KF_DATA_ROOT`):

- **persona view** — when a title maps to more than one lens, which one to read
  in (developer / quality / delivery / executive / curation / operations /
  general);
- **preferred depth** — headline / brief / full;
- **preferred language** — the answer's output language (EN / FR / ES / JA);
- **Explain auto-expand** — whether the narrative opens with the answer.

Invalid or unknown values are dropped; an empty value clears a field.

## How they apply — to every answer, without re-asking

`AnswerService.ask` (top-level only) resolves an **effective principal** from the
stored defaults (`defaults.apply_to`):

- **persona view** routes through an effective `designation`, so every existing
  T27 path (retrieval emphasis, depth, lens, the T84 answer contract, the
  cache scope) follows the chosen lens — no new plumbing;
- **depth** overrides the persona's sentence cap in composition (`_depth_cap`),
  and joins the answer-cache scope so a reader's depth composes its own answer
  rather than serving another depth's cached one;
- **language** renders the finished answer in the preferred output language in a
  single post-hoc pass (retrieval stays on the English source of truth);
- **Explain auto-expand** stamps `answer.explain.auto`, which the Workspace
  honours.

Retrieval is never widened — defaults shape framing, depth, language and the
Explain affordance only; ACL/scope still gates what is retrievable.

## Surfaces & governance

- `GET /api/defaults` returns the reader's stored defaults and the options the
  menu offers; `POST /api/defaults` sets them (per user, **audited** as
  `defaults:set`). The Workspace **Preferences** control loads and saves them and
  re-renders the persona known-question suggestions.
- Showcase: `/api/defaults` is baked (with the option lists) so the menu renders
  in the static demo.

Additive: no existing persona, endpoint or answer path is removed; a reader with
no stored defaults gets exactly the prior behaviour (`apply_to` returns the
principal unchanged).

## Verification

`tests/test_defaults.py`: defaults persist per user and validate (invalid values
dropped, clear works, another subject unaffected); `apply_to` is identity without
defaults; a set persona view changes the answer's lens over the same cited
evidence; depth caps the answer (headline → one sentence) and composes its own
cached answer; the preferred language renders the answer; and Explain
auto-expand is stamped.

Full `pytest` green; `ruff` clean; the Preferences menu bakes into the showcase.
