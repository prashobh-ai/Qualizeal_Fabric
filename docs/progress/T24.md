# T24 — Real retrieval in the static engine + source/asset discovery

Two things ship together: the static engine now does REAL retrieval (not a
lookup of baked answers), and the fabric answers asset/capability questions —
"has anyone made SSO/auth code I can reuse?", "is there an automation script for
X?" — with a ranked list of real organisation assets, across code, tests,
policies and learning material, for any role.

## Broadened ingestion

The build ingests, through the real pipeline:
- **Code**: platform core plus the authentication / SSO / policy building blocks
  (sign-in surface, session-token helpers, the role-and-scope policy check) and
  representative **test suites** (automation scripts).
- **HR / learning / standards**: a vendored Markdown corpus under `corpus/org/`
  — leave policy, the SSO & authentication standard, the test-automation
  playbook, the onboarding guide — so any employee, any role, gets an answer.

## Source / asset discovery (`answer/search.py`)

One `SourceSearcher` interface, two implementations:
- **`IndexedSourceSearcher`** — BM25 over passage text plus a code identifier
  tier (symbol / path), grouped to the best hit per document. Works everywhere,
  including the static showcase.
- **`GitHubCodeSearcher`** — live GitHub code search for a real backend. Dormant
  unless `KF_LIVE_SOURCE_SEARCH` is set AND a token is configured, so the static
  build is deterministic and offline; a deployed backend flips the flag to
  "search the sources themselves", and those hits are exactly the augmentation
  context an LLM is handed at the generation step of RAG.

`discover` fans out across the searchers, dedupes and ranks. The answer service
detects discovery intent ("has anyone / is there / find / reusable / example
of") and returns a discovery answer — a ranked LIST of assets, each linking to
its source (a code hit is line-anchored to GitHub) — never a single synthesised
answer. Code is answered by the identifier tier and discovery only, never
stitched into a prose answer, so a factual question is not "answered" from a
string that merely appears inside a test.

## Real retrieval in the browser (`engine.js`, exported index)

The build exports a compact index into `snapshot.json`: one entry per passage
with its token source, plus document-frequency, N and average length. The
browser engine runs BM25 over it with the same code identifier tier, so a
question that is not baked is retrieved live: composed extractively for a
prose/code question, or returned as a ranked asset list for a discovery
question. Baked answers remain a Level-0 cache; genuinely out-of-fabric
questions still gap honestly.

## Done-when

- Unbaked questions retrieve a cited answer instead of a blind gap: "can I reuse
  any authentication module", "where is the bm25 lexical index implemented",
  "how do I request sick leave" all answer; "what is the capital of France"
  gaps.
- "has anyone made SSO/auth code I can reuse?" and "find an automation script
  for ingestion" return ranked asset lists with source links.
